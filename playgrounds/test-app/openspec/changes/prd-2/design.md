## 产品概述
本方案为低代码可视化应用搭建平台，提供画布拖拽编辑、组件化构建、页面生命周期管理、多人实时协同编辑及数据源绑定等能力。平台面向开发者与业务人员，通过无需编码或少量编码的方式快速产出可发布的 Web 页面。

## 业务架构
### 核心业务流程
用户视角下的典型端到端流程如下：
1. **注册/登录** - 进入工作台
2. **创建页面** - 填写页面名称、路径等基础信息
3. **画布编辑** - 在画布中添加/移动/删除组件，通过属性面板配置样式、数据绑定
4. **预览与发布** - 实时预览页面效果，确认后发布页面使其生效
5. **多人协作** - 与其他编辑者同时修改同一页面，实时可见他人操作
6. **版本回溯** - 查看页面修改历史，必要时恢复到特定版本

### 模块关系
整个系统划分为以下相互协作的后端服务模块（与前端编辑器配合）：

| 模块 | 职责 | 依赖关系 |
|------|------|----------|
| 页面管理服务 | 页面的 CRUD、状态变更、版本控制 | 依赖用户模块（已有） |
| 组件服务 | 提供系统/自定义组件模板的注册、查询 | 无外部依赖 |
| 协同编辑服务 | 实时同步编辑操作，处理冲突合并 | 依赖页面管理服务获取初始快照 |
| 数据源管理服务 | 定义和查询数据源连接信息（如 REST API、数据库） | 可选依赖第三方服务 |

模块间的数据流：
- 前端编辑器通过 REST API 操作页面元数据（页面管理）。
- 进入编辑态时，通过 WebSocket 接入协同编辑服务，接收操作流并提交本地操作。
- 协同编辑服务将操作日志持久化，并定期生成快照供页面管理服务使用。
- 组件服务提供组件定义给编辑器渲染，不参与实时流。
- 数据源管理为页面提供运行时数据绑定元信息，由页面的渲染引擎解析。

## 技术方案
### 技术选型理由
保持与现有技术栈一致，并在稳定、类型安全的基础上扩展协同与实时能力：

- **TypeScript**：全栈类型安全，与现有代码风格一致。
- **Zod**：用于定义 API 请求/响应 Schema、组件 Schema、数据源配置等，保证数据合约。
- **Pino**：结构化日志，便于追踪协作操作与错误。
- **Express**（或现有路由框架）：沿用 `src/routes` 组织方式，新增页面、组件、数据源路由模块。
- **SQLite/PostgreSQL + Drizzle ORM 或 Prisma**：与现有模型层风格统一，存储结构化元数据。
- **WebSocket (ws 库) + CRDT**：选用 **Yjs** 作为协同编辑底层算法，成熟度高，不依赖中心排序服务，降低冲突解决复杂度。
- **事件溯源**：协同操作日志作为事件流，可自然生成页面版本和快照，便于回溯与审计。

### 关键设计决策
1. **“操作日志 + 快照”实现版本与协同**  
   所有页面修改以原子操作记录（如“添加组件”、“更新属性”），协作时广播操作；后台异步合并并定期生成状态快照。版本列表基于快照索引构建，恢复即重放到指定快照。
2. **组件 Schema 化**  
   每个组件类型通过 Zod Schema 定义其属性结构、默认样式、可绑定数据点位等，前端编辑器据此动态生成属性表单，确保前后端校验一致。
3. **数据源抽象为适配器**  
   数据源类型（HTTP、GraphQL、数据库等）由配置驱动，运行时引擎通过适配器注入数据，不与页面编辑强耦合。
4. **RESTful 接口 + WebSocket 通道分工**  
   REST 负责元数据管理、版本列表、组件库、数据源配置等低频操作；WebSocket 仅承载高频编辑操作同步，降低接口复杂度。
5. **零冲突扩展已有 API**  
   新接口完全独立于 `/login`、`/orders` 等已有端点，路径前缀使用 `/pages`、`/components`、`/datasources`、`/collaboration`，不修改现有路由与模型。

## 数据模型
### 核心实体
| 实体 | 字段 | 说明 |
|------|------|------|
| **Page** | `id`, `name`, `path`, `status`（draft/published/archived）, `createdBy`, `updatedAt`, `latestSnapshotId` | 页面元数据 |
| **PageSnapshot** | `id`, `pageId`, `version`, `state`（JSON 完整组件树状态）, `createdAt` | 增量快照，用于快速恢复和预览 |
| **OperationLog** | `id`, `pageId`, `userId`, `opType`, `payload`（JSON）, `timestamp`, `version` | 原子操作记录，支撑协同与历史版本 |
| **ComponentTemplate** | `id`, `name`, `type`, `category`, `schema`（JSON, 由 Zod 生成的 JSON Schema）, `icon`, `createdBy` | 组件库定义 |
| **DataSource** | `id`, `name`, `type`（rest/graphql/db等）, `config`（加密存储）, `createdBy` | 数据源连接信息 |
| **PageDataSourceBinding** | `id`, `pageId`, `componentPath`（定位到组件实例的数据绑定点）, `dataSourceId`, `queryMapping` | 页面内组件与数据源的绑定关系 |

### 实体关系
- 一个 `Page` 拥有多条 `OperationLog` 和多个 `PageSnapshot`（1:N）。
- `OperationLog` 按时间顺序构成页面变更历史，`PageSnapshot` 基于某条日志生成。
- `ComponentTemplate` 独立，在页面状态 JSON 中通过引用 `templateId` 关联。
- `DataSource` 与 `Page` 通过 `PageDataSourceBinding` 建立多对多关系，绑定精确到页面内的具体组件属性。

> 备注：已有 `User` 实体通过 `createdBy` 关联，不新增用户域模型。
