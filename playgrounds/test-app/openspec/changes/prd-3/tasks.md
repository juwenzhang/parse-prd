## 阶段1: MVP核心功能
### 用户通知中心
- [ ] 用户可以浏览按时间倒序排列的通知列表，区分未读/已读状态
- [ ] 用户可以点击单条通知，查看完整通知内容（标题、正文、时间、类型）
- [ ] 用户可以将单条通知标记为已读
- [ ] 用户可在全局头部看到未读通知数的小红点或数字提示
- [ ] 用户在 App 关闭或离线时，仍能收到重要通知的推送提醒（App Push）

### 运营通知管理
- [ ] 运营人员可以创建通知：填写标题、正文内容，从预设类型（如系统消息、活动通知）中选择一种类型
- [ ] 运营人员可以指定通知的发送范围：全部用户 或 按用户标签/ID 筛选部分用户
- [ ] 运营人员可以执行“立即发送”，发送后用户立即或近实时地在通知中心看到该通知
- [ ] 发送的通知会持久存储在系统中，用户可随时回溯历史记录，不会丢失

## 阶段2: 增强功能
### 用户通知中心
- [ ] 用户可以进入“通知偏好设置”页面，对每种通知类型（如评论回复、活动提醒）独立开启或关闭接收
- [ ] 用户可以设置每日免打扰时段（例如 23:00–07:00），该时段内暂停推送通知
- [ ] 用户可以通过滑动或点击删除单条通知，或批量删除多条通知

### 运营通知管理
- [ ] 运营人员可以创建和管理通知模板（增、删、改），在新建通知时可选择一个模板快速填充标题和正文
- [ ] 运营人员可以为每次通知设置发送频率控制，例如限制同一用户每天最多接收该类通知的数量
- [ ] 运营人员可以设定“定时发送”，在未来指定时间自动发出通知
- [ ] 运营人员可以在后台查看通知的发送状态（成功/失败数），并对已发送但用户未读的通知进行“撤回”操作

## 阶段3: 体验优化
### 用户通知中心
- [ ] 通知列表支持下拉刷新和上拉加载更多，提升浏览长列表的流畅度
- [ ] 提供“一键全部标记为已读”按钮，快速清空未读状态
- [ ] 通知支持按类型（或日期）分组折叠显示，方便查找和整理
- [ ] 增加通知搜索框和按类型/状态筛选功能，帮助用户快速定位某条历史通知

### 运营通知管理
- [ ] 通知编辑区域支持富文本（图片、链接、格式化），并可在发送前预览用户在通知中心和推送卡片上看到的样式
- [ ] 提供通知效果数据仪表板，展示每一条通知的发送量、阅读量、点击率等关键指标
- [ ] 支持对同一通知创建 A/B 测试变体，对比不同标题或内容的表现，选择更优版本向全量用户发送
