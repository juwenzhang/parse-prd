# 订单系统

> 老王提的需求，说要搞个订单管理。用户那边老投诉，说下了单不知道在哪看，退钱也退不明白。大概就这些，先写着。

## 大概要做啥

其实主要就是把订单的整个流程管起来。用户选完商品下单，然后付钱，我们这边发货，用户收到货，完事。中间如果用户不想要了可以退。

现在已有的东西：注册登录都有了，用户管理那边也能用。别动那边的代码，上次动一下就挂了。

另外支付那边对接微信和支付宝，信用卡也加上吧，老板点名要的。

## 功能点

### 下单

这个肯定是最重要的，用户选好商品后点下单，生成一个订单。库存要锁定，不然超卖了客服又得来骂人。

- 支持多商品一起下单（购物车那种）
- 多个地址也要支持，有些人一个订单寄好几个地方
- 下单完跳支付页面

对了，金额计算要准，上次那个优惠券 bug 还没修好呢，这次一起搞了吧。

### 看订单

用户能在「我的订单」里面看到自己买过的东西。

有个细节，状态要实时更新。现在的做法是用户刷新页面才更新，体验太差了。最好是推送，但推送可能成本高，先做轮询吧，后面再说。

状态流转大概是这样：待付款 -> 已付款 -> 已发货 -> 运输中 -> 已签收

哦对，如果用户下了单但是一直没付钱，半小时后自动取消，这个功能上次漏了，这次必须做。

### 退款

退款是最烦的，客服那边天天被用户骂。

简单退款（500 以内）系统自动退，大额的要人工看一下。退款完了库存要加回去。

还有部分退款，比如买了 3 件退 1 件这种情况。

退款原因要记下来，运营那边要看数据分析。

对了退款要原路返回，微信付的退回微信，支付宝付的退回支付宝。

### 取消订单

没发货之前用户可以自己取消，发货了就不行了。取消之后钱要退回去。

### 评价

收到货以后让用户打个分，写个评价。有些人会乱写，要审核一下。不审核的话竞争对手来刷差评就麻烦了。

可以传图片吗？用户说想晒图。算了先不做，下个版本再说吧。

## 其他乱七八糟的

- 性能要好点，大促的时候订单量很大，别挂了。上次双十一就崩了，丢脸。
- 退款要有日志，万一用户投诉说没收到退款，我们能查
- 数据存两年够了，后面的归档到冷存储
- 后台要有个简单的管理界面，运营同学能看退款申请、手动审核

关于物流，对接菜鸟的接口就行。不过这个优先级不高，先做核心的。
