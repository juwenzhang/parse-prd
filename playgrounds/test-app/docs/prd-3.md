# 消息通知中心

> 王经理提了好几次了，说现在这个通知完全没法用。用户在平台干了啥、系统有啥消息，根本找不到在哪看。邮件发了也经常被当垃圾邮件，短信又太贵了。得做个统一的站内通知中心。

## 现状是啥样

现在的情况是各个业务线各自发通知。订单那边发个短信，用户那边发个邮件，运营想推个公告都没地方发。而且发了就发了，也不知道用户看了没看。

用户投诉最多的是：退款成功了没通知，货到了不知道，活动开始了也不知道。客户那边天天打电话问。

## 要干啥

反正就是做个集中管理的通知系统。所有的通知都从这里发，用户也能在这里看。

### 通知类型

- 系统通知：系统自动发的，比如订单状态变了、退款到了、账号异常啥的
- 运营公告：运营那边想推的活动通知，可以带图片和链接
- 催办提醒：比如下单了没付款，30分钟后弹个通知催他

还有个站内信，就是用户和平台之间的消息。但那个不急，以后再说。

### 发送方式

要支持多种渠道：站内信肯定是主要的，还有邮件、短信、APP推送。但是短信太贵了，一般情况就别发了，重要通知再发。

APP推送那个找客户端那边对接一下。iOS和安卓都要支持。

### 用户怎么用

用户登录之后右上角有个铃铛图标，有未读的时候显示红点数字。点开了能看到通知列表。

通知要能标记已读。点进详情能看到完整内容。如果有链接（比如运营活动页），点了能跳过去。

还要有个通知设置页面，有些通知用户可以关掉。比如运营推送，用户说太烦了想关掉。但不能全关，系统通知不能关，不然退款成功了都不知道。

### 后台怎么管

运营那边要有个管理页面。能创建通知、定时发送、查看已发送的通知。数据最好能看到多少人收到、多少人点开了，有点击率就更好了。

另外就是模板，很多通知是重复的。做几个模板出来，运营直接选模板改几个参数就发了，不用每次都重新写。

### 用户分群

别给所有人推一样的通知。比如只给最近30天下过单的人推优惠券，只给会员推专属活动。这个后面再做，现在先说。

### 防骚扰

用户投诉太多通知也烦，要做个频率限制。一天最多推3条运营通知，超过就不发了。系统通知不限。

## 技术

- 别用轮询了，用WebSocket推吧，体验好
- 消息要有持久化，不能丢了
- 邮件这个对接哪个服务商？SendGrid还是哪个？
- 统计分析那边后面接数据平台，现在日志先记着
