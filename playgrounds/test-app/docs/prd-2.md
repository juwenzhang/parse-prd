# 协同低代码编辑器

> 一直在说的那个可视化编辑器，这次真的要做了。运营那边天天催，说每次改个页面都要找开发，效率太低了。我们要做一个能让非技术人员也能搭页面的工具。

## 背景

其实去年就在提这个事情了，一直拖着。最近业务方又提了，而且是老板挂名的项目。竞品那边用的人是越来越多了，我们不能落后。

核心问题：运营想快速上线活动页、促销页，开发排期跟不上。一个简单的活动页最快也要3天，太慢了。

## 核心能力

### 画布编辑

最核心的就是那个画布，跟设计软件差不多。用户拖拽组件到画布上，然后调整位置、大小、样式。要有网格对齐和吸附线，不然对齐太难了。

画布要有缩放，能放大缩小看整体效果。还有就是多选，按住shift可以选多个组件一起拖。

层级要能看到，像PS的图层一样，谁在上面谁在下面。

肯定要有撤销重做，不然操作错了就完了。历史记录存个20步差不多够了。

快捷键也要加上，Ctrl+Z、Ctrl+C、Ctrl+V这些基本操作。Ctrl+D复制组件挺好用的。

### 组件系统

肯定不能只有几个组件，要有一套完整的组件库。常用的那些都要有：文本、图片、按钮、输入框、表格、轮播图这些。

而且组件要能嵌套。比如一个容器里面放几个其他组件，这个很常见。Flex布局也要支持，方向、对齐、间距这些。

哦对，每个组件要有个右侧的属性面板。点了组件右边就显示它的属性，然后可以改。比如按钮的文字、链接、颜色、大小这些。

组件还得支持事件绑定。比如点按钮弹出个弹窗，或者跳转页面。这个后面再说吧，先做基础的。

### 页面管理

用户能创建多个页面，有个列表能看到所有页面。可以编辑、预览、发布、删除。页面建多了之后要能搜索和分类。

发布之前要能预览，看看动起来长什么样。预览要真实，不能是静态图。

版本管理很重要，万一发布了有bug能快速回滚到上一个版本。存个10个历史版本够了。

### 协同编辑

这个可能是最复杂的。多人同时编辑一个页面，要能看到对方在改什么。类似Google Docs那种，能看到别人的光标。

冲突怎么处理？实时同步的话肯定会有冲突。我觉得用OT算法，但实现起来太复杂了。CRDT是不是更简单一点？你们评估下。

光标注示别人在编辑哪个组件就行了，深层的同步后面再优化。不过如果两个人同时改同一个组件，还是要有锁，不然会互相覆盖。

权限也需要，编辑者能改内容，观察者只能看。管理员能删页面、邀请人。

### 数据管理

页面数据怎么存？JSON格式吧，存描述页面结构的树形数据。大概长这样：页面有什么组件，组件什么样式，组件间什么关系。

后端API需要：CRUD页面、保存草稿、发布、版本回滚。保存要自动保存，不能让人手动点保存按钮，万一忘了就丢了。
